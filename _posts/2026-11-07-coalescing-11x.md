title: 同一个加法，为什么慢了 11.3 倍
---

两个几乎一模一样的加法 kernel，只改了一行索引计算：一个跑 0.0069ms，一个跑 0.0778ms——**慢了 11.3 倍**。这就是我学 CUDA 的第二个实验，也是"访存模式决定性能"的第一次实证。

## 实验设置

两个 kernel 做同一件事：`c[i] = a[i] + b[i]`，N = 1e6，共 12MB 数据。唯一的区别是线程如何给自己分配下标：

```c
// 合并版：相邻线程访问相邻元素
int i = blockIdx.x * blockDim.x + threadIdx.x;

// 散开版：相邻线程的地址相隔 gridDim（3907）个元素
int i = threadIdx.x * gridDim.x + blockIdx.x;
```

实测（RTX 4070 Ti Super + nvcc 12.6，预热 1 轮 + 3 轮取最小）：

| kernel | 耗时 | 带宽 |
|---|---|---|
| 合并版 | 0.0069 ms | 1744 GB/s |
| 散开版 | 0.0778 ms | 154 GB/s |

ratio = 11.31。

## 第一层原因：32 字节的 sector 交易

GPU 读显存不是按字节，而是按 **32 字节的 sector** 交易——一次交易固定 32 字节，哪怕你只要 4 字节。

一个 warp 有 32 个线程。合并版里，相邻线程访问相邻元素，32 个线程读的是**连续 128 字节**，恰好 4 笔交易，字节全部有用，利用率 100%。

散开版里，相邻线程的地址相隔 3907 个元素：32 个线程落在 **32 个不同的 sector** 里，每笔 32 字节只用了 4 字节，利用率 12.5%。

算总账：

```
有用数据 = 12MB（a 读 4MB + b 读 4MB + c 写 4MB）
散开版每 4 字节有用数据都装在 32 字节的 sector 里 → 交易膨胀 8 倍
实际交易量 = 12MB × 8 = 96MB
```

**12MB 的有用数据，背后实际搬了 96MB。** 这就是 8 倍的来历。

## 第二层原因：L2 的"接单"有上限

如果只是流量差 8 倍，ratio 应该正好是 8。实测 11.31，多出来的 1.4 倍来自请求排队：

L2 处理每笔交易都要占一个请求槽位。合并版一个 warp 只下 **4 笔单**，散开版要下 **32 笔**。单子一多，单位时间能服务的字节数就下降：

```
合并版: 12MB 交易 ÷ 6.88µs = 1744 GB/s  （sector 吞吐）
散开版: 96MB 交易 ÷ 77.8µs = 1234 GB/s  （掉了 1.4 倍）
```

所以完整的拆解是：

```
11.31 ≈ 8（流量浪费）× 1.4（请求排队损耗）
```

## 一个反直觉的细节：11.31 还是"温柔版"

1744 GB/s 超过了这张卡 672 GB/s 的显存峰值——因为 12MB 数据整个塞进了 48MB 的 L2 缓存，合并版测到的其实是 **L2 带宽**，散开版的 96MB 交易也全在 L2 里完成，DRAM 根本没参与。

如果 N 大到数据超过 L2（真实场景几乎总是如此），散开访问会直接落到显存随机寻址上，有效带宽掉到几十 GB/s——**ratio 不是 11，是 20、30 倍**。所以 11.31 是下限，不是典型值。

## 一眼判断访存是否合并

只问一个问题：**相邻的 threadIdx，访问的地址相邻吗？**

| 索引写法 | 判断 |
|---|---|
| `i = blockIdx*blockDim + threadIdx` | 相邻 ✅ |
| `i = threadIdx*gridDim + blockIdx` | 差 grid 个元素 ❌ |
| 二维：`col` 随 threadIdx.x 连续 → 行内连续 ✅；`row` 变化 → 跨一整行 ❌ |

## 一个坑

这个实验是我配好 CUDA 环境后的第一次编译。CUDA 12.6 配的是家里现成的 VS 2026，nvcc 直接报错：

```
#error: unsupported Microsoft Visual Studio version!
Only the versions between 2017 and 2022 (inclusive) are supported!
```

nvcc 12.6 官方支持的 MSVC 上限是 VS 2022 系列，VS 2026 的 MSVC 对它来说太新。解决：补装了 VS 2022 Build Tools（MSVC 19.44），编译通过。

教训：**CUDA 工具链和宿主编译器的版本要一起看**，只查 CUDA 版本是不够的。

## 结论

GPU 编程不是写逻辑，是写访存。让相邻线程访问相邻地址，按 sector 的搬运方式把每笔交易用满——这一行索引公式，就值 11.3 倍。
